# Media Backup Server 0.3.6

Media Backup pairing now uses one renewable authorization code per instance. Codes are encrypted at rest, can be revealed or rotated by the Server administrator, and rotation requires affected Clients to pair again.

Cancelled unpaired records can be deleted. The administrator Web now uses the shared instance overview/detail/configuration/log layout and switches language without a confirmation dialog.

Documentation now reports the unchanged database identity accurately as Media Backup 0.3.0 schema revision 3 and explicitly records that the current sarmg-upgrade matrix does not yet support this state.

Crash recovery now scans only non-terminal commits instead of rehashing all historical uploads every two minutes. Historical upload receipts remain bound to their immutable committed blob even after a resource advances to a newer blob.
