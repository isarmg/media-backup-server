# xszs 1.0.0

此版本将当前实现整理为 1.0.0 发布基线，正式标签为 `v1.0.0`，`main` 从一个初始提交开始。

项目、软件包、命令、服务、安装产物及移动端标识按统一四字母命名表更新；最后一位 `s` 表示服务端，`c` 表示客户端。当前项目名为 `xszs`。公共支撑为一个单体 Rust 包 `xcss`，平台为 Linux AMD64 GNU；管理 Web 构建输入为一个 `@xcss/web` 包。

产品依赖固定到新的 1.0.0 基础库和提交。协议版本、数据库结构版本及第三方工具版本独立管理，不随软件发布版本重置。

升级前导出配置和业务数据，停止并卸载旧名称的服务，再按当前部署指南安装和重新配对。旧数据目录、系统服务及移动应用标识不会自动迁移。基础库项目通过依赖方式接入，无需单独安装后台服务。

参见[项目 README](../../README.md)。

## 内部版本从初始值开始

本次重建的软件发行号为 `1.0.0`。项目自定义的配置、持久状态、数据库 schema、API、通信协议、ABI 和发行清单均以 `v1` 或数值 `1` 作为初始标识；使用语义版本作为身份的配置采用 `1.0.0`。第三方依赖、外部软件 API 和字体上游版本遵循其实际版本要求。

服务端与客户端须成对安装本次 1.0.0 发行物。旧版配置或数据库不直接覆盖新目录；先导出数据并保留备份，再按平台部署文档重新安装和配对。

## 单体公共支撑与当前工作区更改

本项目的 Rust 公共能力只来自一个 `xcss` 包，内部模块已物理合并；整包仅允许 Linux x86_64 / AMD64 GNU。管理页面构建只安装一个 `@xcss/web` 包，原有认证、账户、界面、字体与构建工具改为包内子路径。Cargo 完整 revision、锁文件与唯一 Web tarball 的 SHA-512 integrity 同步核对。

本次提交同时纳入工作区已有的代码、界面和文档修改。部署入口与命令以当前[运维文档](../README.md)为准；历史拆分包的验证不代替最终源码的 CI、平台验收和发行资产核对。

## 当前中立接口与旧版数据处理

当前版本只使用 `.state-instance.lock`、`.state-maintenance.lock`、`.state-maintenance-pending.json` 和 `.state-atomic-` 临时文件前缀；离线升级工具采用 `.release-upgrade` 工作目录。服务身份头为 `x-service`，健康状态中的公共源码修订字段为 `common_revision`。管理会话采用 `__Host-admin-xszs-session`，显式开发模式采用 `admin-xszs-session`；生产 Cookie 的 Secure、HttpOnly、SameSite、Path 和 CSRF 约束继续生效。资源清单格式为 `web-assets-v1`，公共数据库内部表及索引采用 `_common_` 前缀。

这些接口没有旧名称别名或旧版兼容分支。旧版升级前，先按本文的停服步骤停止服务、配套客户端及全部维护工具；确认全部进程退出后，完整备份配置、SQLite 数据库及其 WAL/SHM、业务文件和必要的私有凭据。备份包含敏感数据，应保留原有访问权限并离线保存。

保留旧数据目录，按当前安装步骤配置新的私有数据目录，执行显式 `init` 初始化，随后运行 `config validate`，再启动服务、登录管理页面并重新配对客户端。旧配置应人工审阅后填写当前字段，不能整体覆盖新目录。旧业务数据需要另行处理；当前版本不提供自动迁移。不得让旧、新版本同时写同一目录，不得通过删锁文件或修改数据库 metadata 强制启动；当前结构指纹包含实际表名、索引名和 SQL，仅改名称不能证明数据符合当前合同。
